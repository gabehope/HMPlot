# Changelog before 0.1.0

The development history before the first public release (0.1.0; see ../../CHANGELOG.md),
kept as it was. Versions here were never published.

All notable changes to HeatmapTest (JavaScript) and the `heatmaptest` Python package.
Entries before Unreleased are the release and findings reports that previously lived in
`docs/`, preserved verbatim under their version.

## Unreleased (2.0.0)

2.0.0 is the first release where the JavaScript and Python packages share one version.

### Breaking Changes

- `View` has been removed from the public JavaScript and Python APIs. Use `Plot` with an optional single root `Frame` for coordinates, axes and brushing.
- The spherical orthographic `pole` option has been removed. Its default projection center is now `[0, 0]`; set `projectionCenter` or the viewport's `center` to rotate the globe.
- In a polar `Frame`, `Rect` uses angular x bounds and radial y bounds to draw a sector. Charts that used spherical orthographic sectors should move to `coordinates="polar"`.
- A placed polar or spherical `Frame` fits its whole disk or map inside its `placement.size` box, keeping its aspect. A placed equirectangular map with `size: [100, 100]` is now 100 x 50 pixels; it drew about 314 x 157, since its size counted one radian as half the box. A disk in a non-square box stays round, and a polar inset whose radius domain exceeds 1 no longer overflows. Placed Cartesian frames still span their box, and placed disks with radius 1 are unchanged.
- `Scatter2D`'s undocumented `previous` and `progress` props have been removed. They blended between two positions only on a `Surface`, and setting either turned off the mark's own transitions; mark transitions (`animation`) and `animate()` move points instead.

### Removed

- `Slice`'s `extent` prop is removed: it only set the TransformControls slider's range. A Slider or Playback reading the data gives that range (`min=hm.min("time")`, `max=hm.max("time")`).
- `TransformControls` (Python `hm.TransformControls`), the panel bound to one transform, is removed, with transform handles' `setControl` and the `controls` and `actions` fields of `TransformStatus` (the `TransformControl` and `TransformControlsProps` types are gone). Inputs replace it: put a `Slider`, `Select` or other input beside the plot and read it in the setting. Force's and Provider's actions are trigger props: Force `running` (a Checkbox), `reset`, `reheat`, `step` and `release`, and Provider `refresh`, each read from a Button. Transforms no longer read a Filter's or Slice's column range back from the GPU for a panel. See docs/INPUTS.md, "Migrating from TransformControls".

  ```svelte
  <!-- Before -->
  <TransformControls for={histogram} />
  <Bin bind:this={histogram} x="length" bins={24}>…</Bin>
  <!-- After -->
  <InputContext>
    <Slider name="bins" min={2} max={80} step={1} value={24} />
    <Bin x="length" bins={input("bins")}>…</Bin>
  </InputContext>
  ```

  ```python
  # Before
  hm.TransformControls(target=histogram)
  # After, in a Scene
  hm.Slider(name="bins", min=2, max=80, step=1, value=24)
  with hm.Bin(x="length", bins=hm.input.bins): ...
  ```

### Fixed

- A Slider or Playback whose value, min or max read a reduction of the column a mark drew as x (`value={min("x")}`) left that mark with no positions. `formatDatetime` rejected padding modifiers (`%-d`).
- PNG and SVG exports left the margins around the plot's canvas (legends, titles, captions) transparent; they are painted with the plot's background.
- A VectorTile's internal slots ("tileSlot0 defaults", with their lines and points) were listed in the settings tree.
- A `Line` or `Segments` below full opacity drew at its opacity squared: 0.5 at 0.25, 0.25 at 0.06, and a brush's dimmed rows nearly vanished. `Arrows` ignored `opacity` and drew opaque. All three now blend when their opacity can drop below 1, as points do, and draw at the opacity given.
- Large points in 2D have smooth edges: points in data units (a circle packing's), and points above 16 CSS pixels, blend their antialiased edges instead of using alpha-to-coverage, whose few sample levels Apple GPUs dither into frayed edges. Small points keep alpha-to-coverage, which is cheaper when a million of them overlap.
- A page no longer blocks for about 10 seconds, on a cold shader cache, the first time it draws a Line, Segments, band or Rect through a polar, map or globe frame. The path-refinement pipelines now compile in about a second on an Apple GPU (7.6 s and 2.2 s before), and in seconds on software WebGPU (SwiftShader) instead of never. The drawn paths are unchanged.
- TeX drew only up to its first operator or space: `\frac{1}{x^2+1}` lost `+1`, and `a + b` drew `a`. MathJax 4 splits in-line math into pieces at its breakpoints and only the first was kept; Tex marks (and Markdown's math) now render the whole expression as one piece.
- PDF text in Helvetica, Times or Courier with a character those fonts lack printed as garbage from its first character: a negative tick label ("−5", with the minus sign U+2212 axes use) in the Arial-based themes (538, ggplot, journal, ...) came out as unreadable symbols. The minus sign now prints as a hyphen, and text with any other such character (Greek letters, arrows, primes) prints in the embedded Source Sans 3.
- A missing number is missing: a `null` in a plain numeric array (and an empty cell in a CSV a Provider reads) was drawn at 0, since `Float32Array` reads `null` as 0; it is now NaN, as `undefined` already was, so it is not drawn, not picked and left out of domains.
- 64-bit columns draw. A `BigInt64Array` (or a plain array of BigInts) threw "Unsupported data array type" when uploaded, and a `Float64Array` built a float64 array the WebGPU kernels have no type for. Both reach the GPU as float32, as plain number arrays do; BigInt columns stay exact on the host, so a Facet, Partition or Group keys them exactly, and one past 2^24 logs the warning Python's int64 columns do.
- JavaScript datetime columns keep their precision. A column of Dates (or numbers with a `datetime` schema) reached the GPU as float32 epoch milliseconds, which step by 131 seconds at 2026 dates, so points seconds apart were drawn at one time. Like Python's datetime64 columns, it now counts from its first time. A schema's `unit` is applied (`unit: "s"` was read as milliseconds).
- Datetime tables that start at different times share an axis. Each column counts from its own first time, and the axis took the origin of whichever mark set it last, so a second table was drawn as if it started with the first. The first datetime column on an axis now sets its origin (or an origin the Frame names is kept, where a mark used to overwrite it) and the others are shifted into it. Rect and error-bar ends (`x0`, `x1`, `y0`, `y1`) with datetime columns set a datetime axis as `x` and `y` do.
- Brushing and `nearby` on a datetime column select the rows under the pointer. Brush bounds are epoch milliseconds while a Python datetime64 column's values count from its first time, so a brush over one selected nothing.
- Sibling Frames that each own their x and y (twin axes, as in the "Twin coordinate frames" example) no longer draw the Plot's own empty axes beside theirs: the implicit root showed a [-1, 1] x and y axis, taking the first axis position on each side. The Plot's axes now show when marks plot in its coordinates, directly or through a Frame that inherits one of its dimensions, and axis margins are kept only for axes that are drawn: a Plot whose Frames hide or move their axes no longer leaves empty margins where the hidden root's axes would be (48 px on the left and 36 px at the bottom), so its plot area grows. The documented twin-axis examples (docs/USAGE.md, python/README.md) set `domain: "auto"` on each Frame's y: a Frame that sets only a `label` and `side` inherits the Plot's y and draws no axis of its own.
- TypeScript: the `subscribe` listener of Force, Dodge, Provider, Simulate and transform handles is typed (`TransformStatus`); it was `any`, so a typed app's `handle.subscribe((status) => ...)` failed its type check with an implicit `any`.
- JavaScript types: `PrismProps`, `GeoJSONProps`, `GeoJSONLineProps` and `RoutesProps` keep `MarkProps`' named props. They were built with `Omit` over a type with an index signature, which keeps only the signature, so these components' channels were untyped and missing from the Python stubs (`hm.GeoJSON(fill=...)`, `hm.Routes(width=...)`). `ImageProps` declares `pixelated` and `lit`.
- Python stubs: an expression parameter's list (`bins=[64, 64]`) is a `Sequence`, so a list of ints type-checks; `on_event` lists `camerachange` and `viewportchange` (and a Provider's `load` and `error`), and the event has `frame`, `camera`, `viewport`, `rows`, `ms`, `load_revision` and `message`.
- Python: an unsupported property value names the property and what it accepts. It said "convert device arrays explicitly" for any value, including a pandas Series; that message is now only for torch, jax and cupy arrays. A DataFrame passed as a property says to pass it as `data=`.
- Python type checkers see the package's public names. The stub imported `hm.Scene`, `hm.Table`, `hm.col`, `hm.where` and the rest without re-exporting them (a stub's plain import is private), so pyright reported them as unknown; `hm.animate`, `hm.Animate` and `hm.EASINGS` had no stub at all. The hand-written signatures take sequences instead of lists and tuples (`hm.categorical(domain=[...])` with a list of strings was rejected).
- `enter="fade"` and `exit="fade"` on a keyed update fade Rect, Prism, Segments, Arrows, BillboardArrows and ErrorBars rows too. Only point marks and labels faded: the others' entering rows appeared at once and departing rows vanished at once.
- On a high-density screen (a device pixel ratio of 2), points, line widths, labels and pixel offsets draw at their full size from the first frame. Marks built before another mark's material drew at half size after a page load or theme change, and popped to their size on the first zoom or legend click; SVG export looked larger than the screen for the same reason. three's `screenDPR` made one uniform per material and updated only the newest; every material now shares one.
- Dragging an orthographic globe turns longitude with the horizontal motion and latitude with the vertical, stopping at the poles. It used to rotate along one great circle and stop at that circle's highest latitude, so near a pole a sideways drag that tilted slightly poleward stalled, then turned back, while one tilting the other way ran on: the globe seemed to jump.
- A Plot drawn in a root Frame's coordinates (a polar or spherical Frame wrapping all of its marks) shows that Frame's coordinate settings in its settings pane, and edits them there; the pane read the Plot's unused default ("cartesian").
- A `Heatmap` or `Image` in a spherical Frame placed in a 3D scene draws its globe at the placement, sized, turned and moved with it (a textured planet). It drew a unit globe at the scene's center.
- A plain lit globe (a spherical `Heatmap` or `Image` without relief, at the root or placed) is shaded with the sphere's own normal, so its light falls off smoothly; it was shaded per triangle, in visible facets.
- A `Heatmap` or `Image` in a polar Frame placed in a 3D scene draws its disk in the Frame's plane at the placement (a planet's rings); it drew a small square at the scene's center. A polar Frame placed in 3D fits its outer radius to half its `size`, as in 2D; it scaled one radial unit to half the size, so a disk of radius 2 drew twice as large.
- Each axis a 3D Frame hides (`x={{show: false}}`) drops its edges of the Frame's box, so a Frame with every axis hidden (one that only carries a label) draws no box; it drew the whole box.
- Moving a placed Frame (a new `placement` anchor, size or rotation) only moves it; it re-ran the Frame's whole configuration. The solar system example, 18 placed Frames moving every animation frame, ran at 25 frames a second and now runs at 60. `plot.getDiagnostics().frameConfigurations` counts configuration runs.
- A keyed update that arrives while an earlier one is still animating continues every row from where it is. About half the time a moving row first jumped to the earlier update's target: the new update's staging frame turns the mark's animation off while it writes the union of old and new rows, and an animation frame landing then finished every transition. The clock now holds a mark's transitions during its staging frame.
- A sampled mark whose sample buffer grows (the large force graph's 2048 nodes after a layout step) keeps its picking. Its picking shader kept the old sampled-rows binding next to the new one, under one name, and failed to compile, with WebGPU errors in the console; the picking output is now rebuilt with the mark's material.
- The shared and independent scales example sizes its plots to their columns. They were 1200 pixels wide and overlapped, which hid the legends and most points.
- An embedded `<Pairs>` matrix with a `triangle` (`<Facet layout="grid">` inside a Plot) put its cells in the grid places of a full matrix, row-major; cells now take their row and column (a lower triangle leaves the upper-right places empty). Configuration errors of an embedded Facet now reach `plot.getRenderError()` and the Plot's error display; before, they surfaced only from `whenSettled()`.
- Marks in a frame on a root flat map (a chart on the map) repeat across the antimeridian with the map, on screen and in SVG/PDF export; they were drawn once.
- A Frame that sets its own `coordinates` reads its own angle unit, period, radii and projection defaults instead of its parent's: a globe inside a 24-hour polar dial took its longitudes and latitudes as hours, and dropped points away from its center.

- A north-up orthographic drag stops at a pole without flipping longitude by 180°.
- A click on a `Line` or `Segments` reports the axis value under the pointer; it previously read the line's template geometry.
- A `Ribbon` with `axis="x"` in polar coordinates spans its angular interval along an arc; its cross-section was a straight chord.
- A turned `Rect` inside a log or sqrt parent frame curves its edges like a Line between its corners; its edges were straight chords.
- `Heatmap` and `Image` in polar coordinates draw a disk (angle along x, radius along y); they drew a Cartesian square filling the plot.
- A `GeoJSON` polygon on an orthographic globe that crosses the horizon ends at the limb; its hidden part smeared toward the plot's corner.
- A `Heatmap` or `Image` on a root orthographic globe shows only the front hemisphere; its back half smeared diagonally across the plot.
- `GeoJSON` inside a Frame that overrides its parent's coordinates with a bending parent (a chart on a globe or in a polar parent, a map under log parents) reports that it is not yet supported and draws nothing. It mapped its features through only its own projection, and a diagnosed map could reappear after an option change.
- A curved path's refinement no longer clears other marks' render errors in the same plot when it succeeds.
- A rotated pixel-anchored Frame inside another rotated one kept its pixel size and right angles only in a square plot; in a wide or tall plot it was sheared. Placement rotations now act in screen pixels before pixels scale to world.
- `Text` and `Tex` follow anchored (pixel-placed) and nested polar and spherical Frames; they reported that they were positioned on the CPU and could not. Both draw through `Label`, which maps on the GPU through the whole chain.
- A Plot whose only content is one Frame that sets no domain of its own (so the Frame becomes the root) keeps the Plot's explicit `x`/`y` domains and draws its axes with `axes2d`; it fitted its marks instead and drew no axes.
- Changing a Frame's `projectionCenter` prop no longer re-prepares the marks inside it (and inside its child Frames) or rematches their connectors; the mapping moves through uniforms and the live gather.
- A curved `Arrows` head spans `headLength` along its final chord; it shrank to the last refined piece of the path.
- `ErrorBars` with `axis="x"` in polar coordinates follow their angular arc, with caps across the radius; they were straight chords with caps across the chord, and exported as raster.
- A tangent inset behind an orthographic globe's horizon is hidden until it returns to the visible hemisphere.
- Plot root selection waits for content inside asynchronously prepared wrappers and counts GeoJSON as plotted content.
- Coordinate mode changes clear generated polar and spherical radius defaults while preserving an explicit radius.
- The Tree sunburst gallery and the 2D layering fixture now use polar sectors and render with the new coordinate contract.
- `setViewport({ zoom })` now applies uniform zoom even when stored axis zoom values are present. The connections regression checks a visible translated view after the original zoomed view clips the red endpoints.

### Changed

- One spelling per concept (R2.0): ErrorBars' `axis` is `orientation` (`"vertical"`, the default, or `"horizontal"`), as on Bar, BoxPlot and Violin; Pie's `sort` and Stack's `order` take `"asc"` and `"desc"` (not `"ascending"`, `"descending"`); Summary's column is `field` (not `value`) and Hexbin's fixed grid is `bounds` (not `extent`); Nodes and Edges take `drag` (not `draggable`), as point marks do.
- More single spellings (R2.0): Bar's, BoxPlot's and Violin's band share is `bandWidth` (not `width`, which they now refuse); a line's dashes are one `dash` (true, a dash length in pixels, or `[dash, gap]`) instead of `dashed`, `dashSize` and `gapSize`; RuleX spans `y0` to `y1` and RuleY `x0` to `x1`; Callout's offset is `offsetX` and `offsetY` (not `dx`, `dy`); a label box's outline is `outlineColor` and `outlineWidth` (not `stroke`, `strokeWidth`); Pie's sector text is `sectorLabel` and `sectorLabelFormat`, styled by `textColor` and `fontSize`; an axis hides with `visible: false` (not `show`); Plot's `globeBackgroundVisible` is gone (`globeBackground={false}` hides the globe); both axes are `"xy"` (not `"both"`) in `zoomAxis`, `setViewport`, Facet's `link` and LinkViews; Plot's appearance defaults are `scaleDefaults` (Facet keeps `scales`); Text3D's `content` alias is gone.
- A Plot's axes are its `x`, `y` and `z` (R2.0): `xbounds`/`ybounds`/`zbounds` are `x={{ domain }}`, `xrange` is `x={{ range }}`, `xScale` is `x={{ scale }}`, `xTransform` is `x={{ transform }}` and `axisLabelX` is `x={{ label }}`; the `axes={{ x: {...} }}` object is gone (its `major: { step }` is `step`, `minor: { show, interval }` is `minor` and `minorInterval`, `timeOrigin` is `origin`). Each removed prop raises an error that names its replacement. A Theme's `axes` styles every axis (`fontSize`, `lineWidth`, `tickSize`, the margins); `zScale` is only a number (the height exaggeration). In Python, `axes=True` is `axes2d=True` (`axes3d=True` for a 3D box), and `x_bounds=` is `x={"domain": ...}`; a mark's own bounds keep their names (`hm.Image(xbounds=...)`).
- The interpolation transform is `Interpolate` (it was `Grid`; R2.0). Python's `hm.Grid(columns=2)` is only the layout grid, beside Row and Column; `hm.Grid(x=..., values=...)` raises and names `hm.Interpolate`.
- Python keywords are snake_case only (R2.0): a camelCase keyword (`hm.Points(selectionOpacity=0.2)`) raises a TypeError that names the snake_case spelling (`selection_opacity`). The stubs leave out the settings that duplicate a prop (`fill_color`, `histogram_bins`, `histogram_normalization`, `legend_enabled`, `legend_position`, `font_size`, `label_color`).
- Scale props on marks are named per channel (R2.0; docs/DATA.md "Scales on a mark"): `fillDomain`, `fillRange` and `fillTransform` (`color*` for a color channel), `sizeDomain`, `sizeRange`, `sizeTransform`, `widthDomain`, `widthRange`, `widthTransform`, GeoJSON's `heightDomain` and `heightRange`, and `colormap`. They replace `valueBounds`, `valueTransform`, `scaleBounds`, `scaleRange`, `scaleTransform`, `widthBounds`, `heightBounds` and `cmapIndex`. A flat prop and a `*Scale` object for one channel is an error naming both. A domain may be `"symmetric"`, in the flat prop and in `continuous()`; Heatmap's and Surface's `normalization` is `fillDomain` now (`"symmetric"`, or a domain read from the values as they are). A color range is a colormap for numbers and the palette for categories, and a domain of categories makes the channel categorical in that order. Python follows (`fill_domain=`, `size_range=`, `colormap=`), and the settings pane's edits reach a Python scene under the new names.
- Mark names (R2.0; docs/RENDERING.md "Mark names"): the screen-sized mark takes the short name and geometry in data units takes `3D`. `ScatterPoints` is `Points`, `Scatter3D` is `Points3D`, `BillboardArrows` is `Arrows`, the tube `Arrows` is `Arrows3D`, `Label` is `Text`, and the geometry `Text` is `Text3D`, whose `tex` option replaces `Tex`. `Scatter2D` is removed: `Points` draws the same symbols faster (1M circles at DPR 2: 2.7 ms against 4.1 ms a frame at 4 px, 7.8 against 8.2 at 24 px), so its circle mesh was not carried over, nor its `surface` option. `Links` is removed: `Segments` draws the same curves (`control1`, `control2`) with keys, endpoints and connections. Python follows (`hm.Points`, `hm.Text3D(tex=True)`), and so do theme keys (`theme.marks.Points`) and the reference pages.
- Names in a column's place (R2.0; docs/DATA.md "Field resolution"): `input.bins` (Python `hm.input.bins`) is an expression of its own, so `col("$price")` reads a column named `$price` instead of an input. State is read with `state.time` (Python `hm.state.time`) or `"@time"`; `col("@time")` is now an error that names `state.time`, `hm.dt` is `hm.state.dt`, and `"@offsetX"`, `"@offsetY"` and `"@offsetZ"` are `"@offset_x"`, `"@offset_y"` and `"@offset_z"`. An unknown state name (`state.selcted`, `"@selcted"`) fails at once with the list. Data columns may not start with `@`. `column(values, {type})` is `typedColumn` (Python `hm.typed_column`), and the Python stubs no longer declare the data `Column` class as `hm.Column`, which is the layout.
- Datetime x axes label their ticks by their unit and add a second row where the coarser unit changes (the month and year under day numbers, the date under hours; `axes.x.context = false` keeps one row). A Bin over a datetime column bins by calendar boundaries instead of equal widths. An axis's explicit `timezone` wins over its columns' zone (it was overwritten by the first datetime column). A Group keeps its key columns' categories and times. Python: a 360_day or all_leap time from `Table.from_xarray` is titled by its calendar ("time (360_day calendar)", not its day units), since its axis shows dates.
- One clock per scope (TODO 50; docs/ANIMATION.md "Clocks and scopes"): the Plots of a Python Scene, of an `InputContext` (the outermost), of a standalone `Facet` or under a `Simulate` share `@time`, so their animations stay in step; a plain Svelte Plot still has its own. `setAnimationTime` on one of them sets and freezes the whole scope, and an export of one holds the whole scope. A transform above several Plots of one scope reads `@time` (it was an error over two Plots). Playback and Simulate run on the scope's clock instead of loops of their own: an export or a frozen clock holds them, and each step of `setAnimationTime` moves them, so `export_mp4` records a playing Playback or a running Simulate (a Playback paused to export one frame is no longer needed). A frame's clock step is capped at 250 ms, for `@time` and transitions too.
- Minimaps take their plot's background and text color, and leave text out (labels, TeX, a map's place names). A live `VectorTile` always loads the zoom-0 tile under the rest, so a globe's minimap shows the whole world and a quick pan shows coarse land and water.
- Settings and export are two icon buttons in the plot's lower right, inside the bottom axis margin: hidden until the pointer is over the plot, faint while it is, full on hover or keyboard focus, faint on touch screens (which had no trigger). Settings dock inside a plot at least 480 × 320 on screen and float beside the button on smaller ones; export is its own small panel inside the plot, and the context menu offers it too. The settings tree lists marks under the Plot, labels every row with what it is, and has search and info as icons. The controls take the plot's theme (background and text color) instead of the OS color scheme, and pages can restyle them with `--hm-controls-background`, `--hm-controls-color`, `--hm-controls-accent` and `--hm-controls-font`. A Facet's buttons sit in its top right.
- The 3D orientation indicator (`orientation3d`) is off by default and draws in the lower left; a map's credit line draws in the lower left.
- Antialiasing is one option, `antialias`: `"msaa"` (4x, the default), `"smaa"` (a post pass, about 25% faster on fill-bound scenes, but it softens lines) or `"off"`. It replaces the numeric `msaa` option (`msaa={0}` becomes `antialias="off"`). Exports always render with 4x MSAA, whatever the screen uses (TODO 58).
- A shape column draws any number of shapes at the cost of one: every shape but the circle and square is read from a signed distance field, one texture layer per shape, so the shader no longer grows with the page's shapes and registering a shape rebuilds no mark (it once recompiled every mark with a shape column). A page holds 256 shapes, built-ins included (32 before), and a shape up to 4096 segments (16 vertices before). Polygons may cross themselves; the fill rule decides what is inside. Custom shape codes now start at 23.
- PDF export: the browser's export menu no longer offers PDF, since its in-browser conversion (svg2pdf) mishandles some SVG. Python's `export_pdf` (headless and in notebooks) now prints the SVG export in headless Chromium: vector, text kept as text, the bundled font embedded, and a glyph a font lacks falls back to another font instead of being left out. A notebook view's `export_pdf` needs the export extra. The handles' `exportPDF()` is unchanged.
- A Legend with no `label` (and no scale or mark label to take) is titled by the column its channel plots, as an axis is: `<Legend for={heatmap} channel="fill" />` over `fill="tas"` reads "tas" (TODO 48.6). Pass `label=""` for no title.
- A Heatmap over a grid table passes over dimensions of one coordinate: they count as sliced (a month selected from a series keeps a time dimension of one), and the last two longer dimensions are drawn by default.
- A 2-D Density samples its cells' centres, `(i + 0.5) / resolution` across its bounds, so its cells tile them (they sampled the bounds' ends, and a Heatmap drew them half a cell off): its values shift by half a cell (TODO 51 decision 11). 1-D curves still reach their ends. A 2-D Density grouped by one key is a grid table with a dimension of its groups, and a Grid's and a Density's outputs are grid tables (a Grid's view reports its method as `gridInfo`). A Filter over a grid keeps the grid on its padded form.
- Python's `hm.Plot(title=...)` is drawn by the Plot, not by the scene around it, so `plot.export_png()`, `export_svg()` and `export_pdf()` keep the title; a scene's exports draw it once, from the plot. It looks as before (above the plot, in the theme's font), and `title=hm.input.metric` still works.
- A drag on the orthographic globe keeps the point grabbed under the pointer (north stays up; near a pole, where no turn can, the drag turns longitude and latitude by its motion as before), and a wheel zoom turns the globe to keep the point under the pointer. Before, a drag turned longitude by its length over the radius, so away from the equator the globe lagged the pointer, and a wheel zoom never turned it.
- `VectorTile` is live by default in a 2D view (TODO 35): the tiles the camera shows load as it moves, over the tiles it names. Pass `live={false}` (Python `live=False`) for the previous behavior, where only the named tiles draw; live tiles need opaque styles, and a translucent style is an error on the plot saying so.
- A VectorTile's HTML export embeds its tiles as raw bytes (`tileData`) and keeps its `url`, instead of replacing them with decoded GeoJSON `data` (4–10 times smaller); the page draws them offline and, when live, loads more online.
- GeoJSON marks allocate for 2,048 instances at first, not 250,000, and grow to the next power of two as their geometry needs (TODO 35.0): a VectorTile of twelve tiles went from 725 MB to 153 MB of GPU buffers, and every GeoJSON map needs less.
- The default font is Source Sans 3, bundled with the library (SIL Open Font License), on screen and in exports: axes, legends, colorbar ramps, Label marks and scene and facet titles used `system-ui`, which differs by operating system and printed as Helvetica in PDFs. The built-in themes whose font stack started with `system-ui` (minimal, presentation, colorblind, dark, pastel, graph, sea, sunset, notebook, observable) start with Source Sans 3. Plots load its regular face before they lay out text (`initializePlot()` waits for it, up to 5 s), so text is measured once. The Python bundles are about 2 MB larger each (the four font files, inlined).
- A font stack without a generic family (a theme's `fontFamily: "Roboto"`) falls back to sans-serif on screen and in exports; the browser fell back to its default serif font, and PDFs to Times.
- `Nodes data=` and GeoJSON's `featureKey`/`dataKey` join through the same plan as `Join`: keys are matched on the host through a Map (O(n + m)) instead of comparing every key with every row on the GPU. Their messages are unchanged. A table's key column is read without a readback, and a missing (NaN) measurement key no longer counts as a duplicate.
- A Line or Segments piece that a seam cut leaves as a sliver at a source vertex no longer joins its neighbor across the map (a vertex exactly on a map's seam drew a spike to the other edge). jax mappings of cylindrical maps (connections, line distances) wrap longitudes below -180° as the shaders do.
- A value outside its scale transform's domain is missing, as NaN is, everywhere (TODO 39.1): a zero or a negative on a log axis, or under a log color, size or width scale, is not drawn, not picked, and left out of automatic domains; a negative under sqrt likewise. Before, the shaders clamped it to 1e-6 and drew it far below the axis, while picking, connections, export and legends each did something else. An automatic log axis now leaves such values out and pads in log space, so it stays positive; before, a log axis over data with a zero had no valid domain and drew nothing. A value between 0 and 1e-6 on a log scale is now placed where it belongs; it was clamped to 1e-6. Dash distances on log and sqrt axes no longer compile one shader per transform.

- Python: a compound mark (Histogram, Violin, BoxPlot, Swarm, Bar, Lollipop) accepts the keywords of the building blocks it uses, not of every block compound marks can use: `hm.Bar(x="a", y="b", cap_size=3)` raises "Bar: unknown property 'cap_size'" instead of sending a key the Bar ignores. The registry now follows only the parts of the composition surface a compound mark imports.
- Python: a component accepts only keywords that reach something. Before, it accepted any name its source files or their imports mentioned, and ignored most of them: `hm.Bin(projection="mercator")` did nothing. Now a transform, a data scope or a layout takes its own properties; a mark, Plot, Facet, Frame or axis also takes its settings-pane options; and names the runtime wires itself (`children`, `revision`, event handlers) are refused everywhere. The stubs list every accepted keyword and end without `**props`, so type checkers flag a misspelled one, and `inspect.signature` (Jupyter's completion) shows the same list.
- Python: explicit placement wins over the `with` block that created a component while that block is open. A component put somewhere explicitly, or whose block has closed, still stays where it is. The stubs now say positional arguments are a container's children, and give components that hold no children no positional arguments, so type checkers flag `hm.Plot(df)`.

So a part built inside a `with` block can be added to that block's own node later: `plot.add(legend)`. A component that belongs to another container still raises, now naming that container and suggesting a function that builds one per place.
- Python: the keys of dict options (`Plot(x={...})`, `Frame(placement={...})`, `brush={...}`, `viewport={...}`, `rules=[...]` and the rest) may be snake_case, as keywords are: `x={"tick_count": 5}` is sent as `tickCount`. - Axis text follows the plot's theme. Before, the extra rows were cut off with a console warning. Pointer moves over a brushable mark no longer read data back from the GPU, and a Partition under a Filter keeps the groups whose rows a brush move leaves alone, so their marks and transforms do not run again.

Group, JoinAggregate, Pivot, Summary, Normalize and Stack compute every group at once instead of one pass per group, and Summary reads nothing back unless it bootstraps (then each group's count, once). Uncertainty bands dim with hover, responds and per-row opacity, and GeoJSON fills hide the features at opacity 0; before, these three marks ignored row opacity (docs/RENDERING.md says what it means per mark).

No props or outputs change. Bar (BarGeometry) after a Filter no longer copies the kept rows first: it computes over every row and hides the rows the Filter hides.

The bundled jax-js gains `lax.cellPairs` (the grid's near field) and fixes boolean reductions over comparisons joined by `logicalAnd`, whose WebGPU shaders failed to compile (vendor/jax-js/PATCHES.md, patches 9 and 10).

A column computed from a tweened column in another Calculate is no longer listed as tweened: it moves as data. Without one clock (a Calculate above two Plots), tweens keep the old behavior: the consuming mark blends the channel.

- Dodge (and Swarm) lays glyphs out on the CPU in a worker, from one GPU readback, instead of one GPU pass per glyph: a swarm of 3,000 points settles in about 0.3 s instead of 40, and 30,000 points in about 1 s. Layouts are the same, except that a glyph with two equally near free positions may take the other side.

Building a graph's topology reads back from the GPU at most twice (was up to five times).

Mark components pass `onwheel` handlers to their objects (Prism, Rect, polar Rect and Uncertainty dropped them).

A transform handle's `whenSettled()` now also waits for the marks drawing its output, as a plot's does. A Line whose axis changes no longer rebuilds and uploads all of its data; only a dashed line recomputes its dash distances.

New numbers (a whisker, a window size, bin edges, a width) reuse the compiled programs.

A brush over the brushed-distributions example issues about a quarter fewer GPU operations.
- A mark with `animation` under a Filter keeps the Filter's rows, as a mark without it does: a new selection swaps which rows show instead of preparing the mark again, reading back each row's source row and building a key for every row. It looks the same: rows the Filter shows or hides do so at once, a row that appears while its values change appears at its new values, and keyed tables still match rows by key when the data changes. Marks with `animate()`, `tween()`, `@time`, `enter` or `exit` work as before.
- Each mark's settings pane shows its own outline-width range: a fraction of the radius for points, pixels for Area, Ribbon and ErrorBars. The first mark to mount used to set the range for every mark in the plot.

- BoxPlot (BoxStats, BoxOutliers) and Quantile compute every group at once on the GPU, and grouped transforms after a Filter keep their grouping while a brush moves: a brush move over the brushed-distributions example reads back from the GPU 12 times instead of 51 and takes about 60 ms instead of 100. Density reads its statistics back once and runs each row chunk as one compiled program. Violin, BoxPlot, Swarm, Bar and Lollipop no longer copy a Filter's kept rows to check their orientation.

In the earthquake example, which now computes its depth radius in a Calculate on the globe, a depth-slider step takes 3 GPU dispatches instead of 165 and about 20 ms instead of 50.
- heatmaptest now bundles its own jax-js: `@heatmaptest/jax`, jax-js 0.1.25 with patches (vendor/jax-js/PATCHES.md), and `@jax-js/jax` is no longer a peer dependency. Both return immutable values (`hm.Connect`, `hm.Endpoint`). Endpoints may be defined after the connector. - Python: pointer events on a connector carry `event.connection`: the matched key, the first and last endpoints (`source`, `target`), every endpoint (`slots`) and the two ends of the picked piece (`pair`), each with its row, facet cell, and scene node id, so `event.connection["source"]["node"] == before.id`.
- Protocol: the `{"$connect": {"version": 1, "key", "order", "endpoints"}}` descriptor, with `$ref` endpoint nodes and no data, and the `connection` field of connector `event` payloads (python/PROTOCOL.md, "Connections"). A newer descriptor version is rejected with a message naming both versions.
- Documentation for connections: [docs/CONNECTIONS.md](docs/CONNECTIONS.md) (matching rules, coordinate space, attachments, appearance, events, animation, limitations), reference pages for `connect()` and `Anchor`, a "Connecting marks" section in the Composition guide, the gallery examples "Before and after arrows" and "Parallel coordinates from connections", and `python/examples/52_connect.py`.
- Per-field strip brushing for parallel coordinates: in a Facet split by a Fold's key, a Shift-drag on a cell's axis strip constrains that cell's field (`flipper`, not `value`), constraints on different fields combine with AND, and `@brushed` selects whole observations in every cell. It used to report "Brush channels must be named one-dimensional columns with stable row provenance." (docs/DATA.md, "Brushing").

### Deprecated

- `Pairs` (Python `hm.Pairs`): use `<Facet pairs={[...]} triangle diagonal>` (`hm.Facet(pairs=[...])`). `<Pairs>` with `<Facet row="yField" column="xField">` still builds the same cells, keeps its `"shared"` default and filter-only orders, and warns once (Python: `DeprecationWarning`). A Facet with `pairs` or `fields` inside `<Pairs>` is an error.

- `Scatter2D` `pixelSize`: use `size` (pixels are the default `sizeUnits`). Still works, warns once.

- `shapeField` (Python `shape_field`): pass the column to `shape` instead. It still works for this release and logs a deprecation warning.

### Fixed

- A Slice with a single entity (no `by`, or one key value), a Sort over one row, and anything else that sorts a one-element array failed on WebGPU: the bundled jax-js generated an invalid shader for one-element sorts (upstream jax-js 0.1.25 does the same; fixed in vendor/jax-js patch 7). Such a Slice drew nothing.
- A Slice after a Filter recomputed the range of its time control from the kept rows on every run (a readback and GPU programs for each new row count), shown or not; it now reads the unfiltered rows once.
- In a 2D view, marks now draw in the order they are written: a later mark covers an earlier one where they overlap, even when the earlier mark's data finishes preparing last (a DAG's `<Edges><Routes /></Edges>` written before `<Nodes>` used to draw over the node circles), and whether each mark is opaque or translucent (a translucent Ribbon, Area, Image or Label used to cover every opaque mark). Reordering components reorders the marks; picking, PNG, SVG and PDF export follow the same order. A Heatmap's value relief and the depth of Arrows' solid shafts apply only in 3D now, so in 2D they no longer cover marks written after them. 3D views are unchanged. See docs/RENDERING.md, "Mark order in 2D".
- BoxPlot and Violin with a category axis ordered differently from the data (`xScale={categorical({ domain })}`) drew the whiskers, medians and violins on other categories than their boxes; they now follow the axis order.
- An empty group's BoxStats or Summary statistics compiled a new GPU program for each pattern of empty groups (a literal NaN folded into the kernel).
- A plot whose data changes every animation frame (for example a Slice at an animated time) now appears and animates. It used to stay behind its loading indicator until the changes stopped, because every new input aborted the transform run in progress, so nothing was drawn, and `whenSettled()` never resolved. A transform whose input changes while it runs now finishes and draws that run, then runs the newest input; `whenSettled()` resolves once the changes made before the call are drawn and no longer waits for changes made after it. It also waits for what those changes rerun, in linked plots too: a brush or pick applied a frame after its pointer event, and a plot's first data after its GPU initialization.

- A Group after a Filter that keeps no rows no longer fails with "Index 1 out of bounds".

- A Sort by several fields (`by: ["a", "b"]`) reversed its `by` list in place, so every other run (each brush move or data update) sorted by the fields in the opposite order.
- BoxStats over no rows (for example after a Filter that keeps nothing) no longer fails with "Need at least one array to stack", nor JoinAggregate, Quantile, Pivot or Density with `by` over an empty table.

- Labels and 3D points no longer rebuild their material, and compile new render pipelines, whenever their opacity changes; a spherical Text no longer compiles new pipelines when it moves or resizes; and a changed display pixel ratio no longer changes label, point or offset shaders.

- A Filter or `Bin weight` that reads an interaction column (`"@brushed"`, `"@selected"`) of a `Data` table no longer leaks a full-length GPU mask each time it reruns; brushing a large table grew GPU memory with every move.

- A reduction inside an `@time` channel (`add(mean("r"), multiply(std("r"), sin(divide("@time", 1000))))`) re-ran its GPU reduction on every animation frame (a full sort for `median` and `mode`, once per group with `by=`). It is now computed once per data revision and reused across frames.
- TypeScript rejected an expression condition on `Filter` (`where={greater("x", mean("x"))}`), which the runtime accepts: `FilterProps.where` now includes `Expression` (alone or in a list) and is documented, and the Filter reference describes expression conditions.
- Python stubs typed `Bin.bins`, `Histogram.bins`, `Density.bandwidth`/`resolution`, and `Grid.resolution` as `Any`; they now spell out their accepted values, such as `float | Literal["auto", "sturges", "fd", "scott"] | list[float] | Expression` for `Histogram.bins`.
- A Label compiled a new GPU pipeline on every data update (twice per keyed update), because each new set of texts baked its atlas layout into the shader. The atlas is now passed as a uniform and a swapped texture, so changing a Label's text no longer recompiles it.
- A channel reading `@time` compiled a new GPU kernel on every frame it ran (the clock value was built into the kernel's code), so an orbiting mark kept the GPU compiling for as long as it was on screen. The clock now reaches the GPU as a buffer value and the kernels are reused.
- In the animation-engine example (and Python example 47), the orbiting `@time` satellites jumped to new positions on every keyed update while the points beside them glided: a `@time` channel has no transition, so the data part of it moves at once. The satellites now sit on a `Data` of their own with fixed slots, so the clock is their only motion; docs/ANIMATION.md shows the pattern.
- A Prism or Rect whose `width` named a column failed to render with "Unknown option widthBounds on ..." (the Facets & transforms example's hexbin view, whose Hexbin output feeds `width="width"`): the column was bound to a stroke-width scale that these marks do not have. Their `width` is now read as a size in data units, like `depth`. When a mark fails inside an error boundary, the boundary now shows that error instead of "Cannot read properties of null (reading 'props')".
- Documentation site: "Edit Python" cells failed on every snippet with "No module named 'heatmaptest.expressions'", because the in-browser Python runtime did not ship the expressions module added with reductions. It does now, and the cell opened from a guide example is labelled "Edit Python" like the one on reference pages.
- Scatter2D and Scatter3D drew RGBA alpha and per-row opacity arrays fully opaque (only ScatterPoints blended); they now blend, which also makes selection fading visible on Scatter2D. Hover or selection on a 3D point cloud where nothing is dimmed no longer cuts light halos around overlapping points.
- SVG and PDF vector export wrote only the mark's opacity, so RGBA alpha, per-row opacity, and faded unselected rows exported opaque; each element now carries its own opacity.
- A Label with per-row colors and per-row opacity (N x 4 colors, `hm.rgb(..., a=)`, an opacity array, or selection fading) drew nothing, because it needed more GPU vertex buffers than WebGPU allows; it now draws. A point or label mark whose per-row channels still exceed the limit (for example RGBA fill, RGB outline, and per-row size together) reports an error naming the mark and its channels instead of drawing nothing.
- Python: `hm.continuous()` without a colormap drew Viridis even under a Theme with its own `colormap`; it now follows the theme's colormap like JavaScript's `continuous()`, and `scale.update(colormap=None)` returns to that default.
- Custom colormap colors with alpha (`rgba()` below 1, `transparent`, 8-digit hex) were drawn opaque (`transparent` as black) in plots, legends, and exports; JavaScript and Python now reject them with an error pointing to the mark's `opacity`. Evenly spaced `positions` (such as `[0, 1]` for two colors) normalize to none, so an equivalent map no longer takes a second colormap slot; Python's `hm.colormap(..., positions=[0, 1])` now returns `positions: None`.
- Custom colormaps were limited to 224 per page, counting every colormap ever used, so editing a scale's colormap interactively eventually fell back to Viridis with only a console warning. Colormaps that no mark has drawn for a second now give up their slot; only more than 224 custom colormaps on screen at once is an error, reported on the plot.
- `Image` drew every color at twice its linear intensity (mid-tones too bright, light colors clipped), and categorical Grid heatmaps, which share its path, drew their palette colors darker (`#4c78a8` as `#1d458a`); both now render the exact colors. `Image` RGB data follows the RGB rule: integer arrays (including NumPy uint8 from Python) are 0-255 instead of being clamped as 0-1 floats, and out-of-range values are an error. `Heatmap` given `[height, width, 3 or 4]` colors used to draw nothing silently; it now reports an error pointing to `Image`.
- Settings pane: a mark with a custom colormap showed a blank colormap select and a white preview; it now shows "Custom" with the colormap's own gradient, and choosing a built-in name still replaces it.
- A `BoxPlot` without `orientation` inside `<Data>` did not render (Svelte `state_unsafe_mutation` error): `<Data>` updated its error message while the BoxPlot was reading the table to pick its orientation.
- A `Line` drew nothing when its per-row channels needed more GPU vertex buffers than WebGPU allows: any two of them (for example per-row colors with an opacity column, selection or brush fading, or a `width` column), or any one on a dashed Line. Lines and `Segments` now take two fewer vertex buffers, so a Line fits per-row color, width, and opacity together (a dashed Line fits two of them). A `Line`, `Segments`, `Arrows`, or `BillboardArrows` whose per-row channels still exceed the limit reports an error naming the mark and its channels instead of drawing nothing.
- A Shift-drag on a Frame's axis strip brushed nothing when the brushable marks sat in a child Frame that inherits that axis, for example a Frame inside every embedded Facet cell that owns x and plots on the cell's y axis: a strip took its column only from marks directly in its own frame. A strip now also counts the brushable marks of descendant frames that inherit its axis through every frame in between; marks that plot different columns there are still reported as ambiguous, and where strips nest the innermost one still wins.
- A child frame dimension that no mark plots on drew an axis anyway, using an ancestor's domain read through option inheritance: a Frame in every embedded Facet cell that owns x left each cell with a lone "0" tick and an "X" title. A child frame's own dimension now draws its axis (ticks, labels, title, grid) only once it has a domain: an explicit one, a categorical scale, or the extent of marks that plot on it. An explicit domain still draws with no data, and the root frame of an empty plot still draws its default axes (docs/FRAME-IMPLEMENTATION.md).
- `axes2d={false}` on a Plot did not hold once a Frame with a hidden axis sat anywhere inside it: a Frame in every embedded Facet cell (whose inherited y axis is hidden) re-derived the root's `axes2d` from all frames and drew the root axes over the facet's layout extent (x from -0.5 to 3.5, y about -0.4 to 0.4) and moved the axis margins. Only frames that draw on the root rect's sides (the root, a View's Axes, twin axes) now count, spatial frames (ranged or anchored Frames, facet cells, and Frames inside them) never do, and an explicit `axes2d` prop always holds; without the prop, a twin axis still turns the root axes on.
